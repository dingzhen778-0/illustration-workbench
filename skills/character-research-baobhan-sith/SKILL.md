# A：角色参考研究

输入：用户 brief、已有参考、本次服装／灵基版本。输出遵循 `../baobhan-sith-workflow/references/handoff.md`，写入项目 `01_character_research/`。

单独调用时先定位用户项目与已有 brief；缺少完整档案时从用户已给图片和约束补最小记录。仅修现有图像时不强制重跑无关阶段，但要检查本次修改依赖的身份／结构输入。

## 研究与证据

1. 检查用户图像和档案，再补缺失参考。搜索词可用“巴万希／妖精骑士崔斯坦／Baobhan Sith”及明确版本。优先游戏官方／发行方素材；二手资料用于定位原始来源，同人用于动作、氛围等辅助。
2. 逐张看图，确认它属于哪个版本；来源标签与画面证据分开记录。不能只凭搜索缩略图或文字剧情写出瞳色、饰物结构等视觉结论。
3. 在 index.json 记录来源、版本、用途与未知项。按当前任务整理 official、fanart、pose、face、costume、lighting 分组；只保存需要且允许获取的素材，无本地图时保留来源链接并标未下载。
4. 以 [上游角色表](references/upstream-character-template.md) 的 Appearance／Costume／Expression／Visual Reference 字段作为起点，改成单角色档案；删除漫画角色列表、传记年龄变化和生成参考表的默认要求。未知内容留未知，不照抄模板示例。
5. 提取：发型／五官／服装结构／配色／标志饰物／比例关系；每个固定项指向 ref_id。区分官方可见事实、用户改设、同人观察与推断；不要把“病娇／残酷”等解读直接当成官方视觉事实。

为对象生成交接时，将头部/五官、前后发与发束、肤面、服装结构和饰物分别对应参考区域；区分轮廓/固有色、纹理材质、光照用途。参考中的光源不自动覆盖本项目已确定的光源。未知遮挡部位保留推定标记。

当前若有 reference-media-analysis、character-design-continuity 或 visual-style-direction，按相关阶段读取，复用其台账和连续性方法；不存在时用上面的最小流程完成，不将它们伪装为已安装依赖。

## 验收与交接

- 有一个可执行的所选版本及身份参考；版本未确定时可继续搜集与对比，但不宣称角色设定已锁定。
- B 所需的脸、服装轮廓、饰物和配色有可读取证据；缺失部位标明，不凭同人填成官设。
- 固定项与可变项清楚；冲突参考已处理或隔离。选定设定和参考索引形成稳定输入版本。

通过后交接 character_profile.md 与 index.json；不因研究阶段默认生成新设定图。不可读取关键图像时报告具体缺口；文字检索结果不替代视觉核验。
